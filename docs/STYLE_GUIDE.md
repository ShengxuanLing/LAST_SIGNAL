# LAST SIGNAL — 美术风格指南

> 版本 v1 · 面向"为这款游戏做美术"的唯一指南。
> 所有色值、尺寸、元素均取自 `src/` 现有代码（`core/GraphicsFactory.ts`、`world/WorldRenderer.ts`、`scenes/*`、`config/*`）。
> 本游戏**没有外部图片资源**：所有纹理由 canvas 程序化生成。改动时遵循下面的规则，画面就不会跑偏。

---

## 0. 一句话定位

**科幻 / 科技威胁主题**的俯冲竞技场刷怪射击（roguelike 房间深度）。玩家是一个被青色外框勾勒的机械构造体，在深蓝几乎纯黑的设施里对抗各色无人机。视觉靠**青色的"我方/系统"感**与**橙/红/紫/金的"威胁/奖励"感**对立来读。

---

## 1. 美术支柱（Art Pillars）

1. **暗底 + 单色辉光**：背景永远接近纯黑（海军蓝），物体几乎只靠描边色与内发光被看见，没有复杂贴图或阴影纹理。
2. **几何极简**：敌人/道具都是圆、菱形、菱形星等基础图形，加一条一致的描边。不引入写实或有机形状。
3. **青色为"系统/我方"基色**：界面、玩家、能量弹药统一青色；橙/红/紫/金只用于**敌人、威胁、稀有奖励**，用来瞬间区分阵营。
4. **数据驱动的秩序感**：所有东西按房间深度、权重、等级缩放生成——画面也要透出这种"被计算的、可复制的"整洁。

**绝不做的**：写实照片风、暖色渐变背景、手绘笔触、彩色噪点纹理、Logo / 通用商业插图、写实光影。

## 3. 线条与光照（Lines & Light）

- **统一描边**：几乎所有有生命/可交互的实体都有 2–3px 纯色描边（敌人 2.5px，玩家 3px）。描边色 = 它的阵营/功能色。**不加轮廓阴影，只加描边。**
- **内发光优先**：实体内部用一个亮点/圆心点表达"能源核心"——敌人用圆形高光（`r≈4`，描边色），玩家用顶部亮条（`#7ff0ff`）。
- **软辉光 = 弹药/特效**：弹药与技能用 `radial()` 径向渐变（中心亮、外圈 `rgba(0,0,0,0)`），制造辉光晕，不画硬边弹体。
- **投影只有一条**：每个实体底部一条淡椭圆阴影（`rgba(0,0,0,0.35)`），用于定位、不用于氛围。
- **光源概念**：没有方向光。世界自身是暗的，唯一"光源"就是青色系统光与各色弹药/核心的辉光。所以**描边与发光就是全部信息**。

## 4. 精灵与图块规格（Specs）

游戏运行时 **1280×720**。等距世界：`TILE_W=64`，`TILE_H=32`（2:1 等距）。所有纹理为 canvas 生成、按 `NEAREST` 采样（保持硬边像素感）。

### 4.1 图块（tiles）— 64×64
- 地板 / 墙均为 64×64，四角带青点或带橙色警示块区分类型。
- 新增地板/墙类型时：**复用同一套深海军蓝底 + 同色描边网格**，只改顶部的类型标识色（水→`#1a3a44`、火/熔岩→橙色系、出生点→单独）。

### 4.2 单位精灵（按当前实现）

| 实体 | 画布 | 形状 | 主体色 | 阵营色 |
|---|---|---|---|---|

## 5. 界面 / HUD 规则

- **字体**：等宽 monospace；文字色用冰白 `#eafaff`，状态色走色板。
- **按钮**：深色底 + 青色边框；选中态 = 青色填充 + 亮青描边（见主菜单截图）。
- **副文本 / 提示**：`#8fb8c8`、`#5a7480`（如操作提示 "WASD move · MOUSE aim · ..."）。
- **信息色**：血=红、货币=金、升级=青、武器=橙、Boss=红/金。保持与上面功能色一一对应。

## 6. 动效与反馈节奏

取自 `config/game.ts`，保持这套数值以免节奏跑偏：

- 伤害数字存活 `DAMAGE_NUMBER_LIFE = 0.8s`，带上升 `vy`。
- 屏幕震动 `SHAKE_MAX = 18`，衰减 `SHAKE_DECAY = 6`。
- 相机 lerp `CAM_LERP = 0.12`；缩放区间 `CAM_ZOOM_MIN 0.8` ~ `CAM_ZOOM_MAX 1.25`。
- 受击闪：`EnemyData.hitFlash`、眩晕 `stunTimer`；用描边色做一次高亮闪烁后恢复。

## 7. 新增/复用时的检查清单（Checklist）

1. **阵营归类**：新元素先定"青色系统 / 威胁 / 奖励"三选一，选错颜色就读错。
2. **复用现有生成器**：敌人用 `drawEnemy()`，弹药用 `radial()`，不要写全新画风。
3. **颜色来源**：只从第 2 节色板取 hex；**禁止发明新色**。
4. **尺寸对齐**：图块 64×64、图标 24×24、单位按第 4.2 节。
5. **保持硬边**：`FilterMode.NEAREST`，不引入模糊/羽化（径向辉光是唯一软边，且限于弹药/特效）。
6. **无外部资源**：新增美术也走 canvas 程序化，不要塞 PNG/JPG。

## 8. 一致性核对（可本地执行，无需联网）

本游戏自带一套核对逻辑（见 `sable-game-art-evidence` 思路）。对任何新产出的图，可核对：

- **调色板外颜色**：是否只用了第 2 节色板内的 hex / rgba。
- **画布尺寸**：是否为 64×64 / 24×24 / 48×48 等规范尺寸。
- **网格整除**：等距 64×32 是否对齐，房间深度生成是否正确。
- **空帧 / 杂边**：canvas 图是否干净、是否有不该有的半透明杂边。

需要时我可以把这份指南连同核对脚本一起落到 `docs/` 下，或对某张具体的新图做一致性审查。
