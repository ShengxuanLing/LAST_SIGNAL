## 0. 一句话

**零号站不是为玩家建造的关卡，而是一座仍在按时执行、却早已没人签核的观测设施。**
玩家看到的每一盏灯、每一块铭牌和每一条管线，都应当回答"这里原本做什么"，同时留下"为什么现在还在运行"的问题。

## 1. 审计结论（修改前）

| 项 | 现状（origin/main @ 860a0dd） | 问题 |
|---|---|---|
| 渲染 | Phaser 3.90，`Phaser.CANVAS`（无 WebGL：无着色器、无 tint、无光照管线） | 所有"光"必须由预渲染纹理 + `ADD` 混合实现 |

## 2. 世界方向：三个区域，一个设施

三种方向不是三种风格，而是**同一座设施在不同损坏程度下的三层**。它们共享材质、色彩与 Signal 语法，只在比例和"秩序 / 失稳"的配比上不同。

### A. Abandoned Infrastructure — 废弃基础设施（R2 失稳走廊为主）
- **结构先于装饰**：格栅地板、承重肋、生锈主管线、危险边条。尺度靠"重复结构 + 远处继续延伸"表达，而不是放大物件。
- **工业历史**：补焊过的格栅、坠落在深渊底部的旧桥段（`wreck`）、"上次巡检 ———— · 结果：通过" 的铭牌。
- **已实现**：`CORRIDOR_THEME`（grating 地面、深渊纵深与断崖面、旧桥残骸、四个桥体发射柱、巡检坞站）。

### B. Signal Anomaly — 信号异常（叠加在任何区域之上）
- **异常有规律**：失稳不是随机闪烁。桥在 `UNSTABLE` 时抖动幅度、裂纹数量、闪烁频率随剩余 tick 单调增长；故障灯按固定节奏图案闪烁（`pattern: '1111011101000000'`）。
- **状态残影**：失稳桥体旁出现位移的"前一状态"轮廓（GDB §12.4 "短暂的状态残影"）。
- **已实现**：桥体五态、Jam 干扰（锯齿折线 + 剩余时长环）、扫描时效衰减。

### C. Silent Machine Civilization — 沉默的机器文明（R1 观测实验室为主）
- **秩序与重复**：规整的观测地板、成排的维护面板、对称的门框；冷色、低环境光。
- **无人的自动化**：停在轨道中段的样本车（琥珀灯缓慢闪烁）、"等待人工确认_" 的终端、"维护周期 #4117 · 自动签核 ✓ / 人工签核 ——"。
- **已实现**：`LAB_THEME`。

## 3. 色彩系统（调和 STYLE_GUIDE 与 GDB §12.3，回应 X-05）

保留 `STYLE_GUIDE.md` 的全部既有 hex，只新增**一个**语义色（冷蓝 `#5d8dff`）和一组**不承载语义**的材质灰。

| 语义 | 色 | 线型/动态（不只靠颜色） |
|---|---|---|
| 可交互协议端点 / 玩家发出的动作 | 青 `#33e0ff` | 实线环 |
| 稳定的载波 / 正在供给 | 冷蓝 `#5d8dff`（新增） | 流动脉冲，方向 = 源 → 汇 |
| 未知 / 不稳定 / 即将过期 | 琥珀 `#ff8a3c` | 闪烁；频率随风险上升 |
| 敌对控制 / 封锁 / 危险 | 红 `#ff3355` | 流向敌方的脉冲；封锁门的危险条 |
| 干扰（Jam） | 紫 `#a398ff` | 每帧重掷的锯齿折线 + 倒计时弧 |
| 高优先级观测事件 | 冰白 `#f2fbff` | 扫描命中的十字 + 扩散环 |
| 未观测 / 无输出 | 灰 `#5a7480`（线条提亮至 `#8fb8c8`） | 静态虚线 |

可读性：`src/visual/visual.test.ts` 断言所有语义色相对最暗/最亮地板材质对比度 ≥ 3:1（灰除外，灰只用于"无效"）。

## 4. 光源层次

Canvas 渲染器没有动态光照，因此光分三层"画"出来：

1. **环境基调（烘焙）**：远景背景径向渐变 + 墙脚环境光遮蔽（AO 渐变带）+ 屏幕边缘暗角（"未观测区域"）。
2. **设施光（动态、有节奏）**：天花灯具（有一盏按固定图案失效）、终端/样本车指示灯、深渊下方的远光。
3. **语义光（动态、由状态驱动）**：门状态光、中继器灯、桥体发射柱、守卫灯、扫描/干扰闪光。只有这一层允许高亮度。

规则：**同屏最亮的东西必须是玩家此刻需要做决定的东西**。环境光强度上限由主题 `ambientIntensity` 控制（实验室 0.32，走廊 0.24）。

## 5. 材质语言

| 材质 | 用途 | 处理 |
|---|---|---|
| 观测地板（钢板） | R1 | 板缝 + 两条受光倒角 + 变体（分割、通风格栅、检修盖、螺栓） |
| 格栅 | R2 | 双向格栅条，下方近黑；少量补焊板与锈斑（≤13% 地块，避免图案化） |
| 混凝土 / 钢 | 墙体 | 三面明暗（顶 > 西南面 > 东南面），踢脚暗带，内隔墙带老化警示条 |
| 锈 / 污垢 | 磨损叙事 | 只出现在"有原因"的地方：管线、角落、长期行走路径 |

## 6. 场景尺度

- 墙高分三级：**后墙 54–60px**（永远在实体之后，承载铭牌/管线）、**内隔墙 30px**、**前缘 8px 路缘**（永远不遮挡玩家）。这是等距视角下保持可读性的关键取舍。
- 背景：巨型观测环（GDB §12.2 "巨型环状观测装置"）与两列向远处退去的塔柱，暗示房间只是更大结构中的一个舱段。

## 7. 视觉叙事原则

- **记录而不是说明**：只用铭牌、终端日志、地面喷字、维护编号；不写成段说明文字。
- **不冻结真相**：凡涉及年代、时长、来源的字段一律写成 `——` / `————` / "记录无法解析"（对应登记册 W-01/W-02/W-03 仍为 `NEEDS_USER_DECISION`）。
- **环境暗示 ≠ 信息泄漏**：实验室地面电缆通向隔墙方向，但封锁源/接收器的位置与连接**只在合法扫描后**显示。

## 8. 不做什么

- 不做大面积霓虹、不做无意义的发光、不叠加全屏粒子。
- 不改变碰撞、可通行区域、LOS、tick、RNG、伤害、存档、输入或 HUD DOM。
- 不把 Guard 的内部状态（证据坐标、视野半径、攻击前摇）画成全知 UI，详见 VISUAL_LANGUAGE §6。
