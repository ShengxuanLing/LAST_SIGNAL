# LAST SIGNAL
## Game Design Bible — 世界观与核心玩法设计圣经

**文档版本：** 1.0 Draft  
**项目名称：** LAST SIGNAL  
**游戏类型：** 2.5D Reality-Engineering Action Roguelite  
**技术基础：** Phaser 3.90 / TypeScript / Vite  
**首发平台：** Web

**开发路线：** Signal Gameplay + AI-Native Integration

# 0. 文档定位与使用原则

## 0.1 本文档的目的

LAST SIGNAL 已经具备一定的动作 Roguelite 技术基础，包括移动、射击、冲刺、敌人、武器、升级、随机房间和 Boss。

但这些系统本身不足以形成具有鲜明辨识度的游戏。

本设计文档旨在回答五个问题：

1. LAST SIGNAL 究竟是一款什么游戏？
2. 玩家为什么应该选择它，而不是其他动作 Roguelite？
3. 游戏世界为什么会存在这些特殊机制？
4. AI 在游戏中为什么是不可替代的第二主角？
5. 后续所有功能应该围绕什么目标进行开发？

本文件为开发团队、AI Agent、关卡设计者、叙事设计者及测试 Agent 提供共同的设计依据。

## 0.2 当前确定的产品方向

以下内容属于已经明确的高层产品方向：

- 核心体验：操纵现实、发现世界规则。
- 世界氛围：神秘、孤独、宏大的科幻。
- AI 定位：拥有独立意识和目标的第二主角。
- 技术路线：保留现有 Phaser 游戏基础。
- 平台策略：先 Web，后 Electron。
- 开发策略：稳定推进，每阶段独立验收。
- 核心研发路线：Signal 系统与 AI-Native 系统并重。

## 0.3 设计提案与已批准实现的区别

本文件中的世界观细节、剧情年份、角色名称、技能参数、具体关卡和结局均属于 **V1.0 创意提案**。

除用户明确确认的高层方向外，不应自动将其视为已经批准的技术规格。

开发 Agent 必须区分：

- **产品方向：** 指导所有设计的长期目标。
- **候选设定：** 可根据叙事与玩法验证调整。
- **待冻结规则：** 需要明确数值、接口和状态转换。
- **已实现功能：** 必须通过真实源码与测试证明。

# 1. 游戏核心定义

## 1.1 一句话介绍

**LAST SIGNAL 是一款关于发现现实运行规律、操纵局部因果关系，并与具有独立意识的 AI 共同探索失稳宇宙的 2.5D 动作 Roguelite。**

英文定位：

> LAST SIGNAL is a reality-engineering action roguelite where a human and an artificial consciousness uncover the rules of a collapsing universe—and learn to change them.

## 1.2 核心设计命题

传统动作游戏关注：

> 我应该如何击败这个敌人？

传统解谜游戏关注：

> 我应该如何解开这个机关？

LAST SIGNAL 希望玩家进一步思考：

> 为什么这个敌人会攻击我？

> 为什么这扇门必须关闭？

> 为什么这座桥只能在某些条件下存在？

> 如果我改变造成这个结果的规则，会发生什么？

玩家不仅需要战斗，还需要理解现实的运行方式。

游戏最重要的成长不是数值提升，而是玩家对世界规律的理解不断深化。

## 1.3 核心品类概念：Reality Engineering

**Reality Engineering（现实工程）** 是 LAST SIGNAL 的核心玩法名称。

它不等于魔法，不等于自由修改游戏代码，也不等于任意创造物体。

现实工程指：

玩家通过观测、实验和推理，发现世界中某个实体的状态依赖关系，再利用有限的工程工具改变该关系，从而改变游戏世界的实际结果。

标准流程：

**Observe → Hypothesize → Experiment → Understand → Manipulate → Consequence**

中文：

**观察 → 假设 → 实验 → 理解 → 操纵 → 承担后果**

这一流程必须成为游戏设计、关卡设计和系统设计的共同基础。

## 1.4 三大设计支柱

### 支柱一：知识本身就是力量

玩家不应只依赖解锁新技能获得成长。

理解敌人、环境和现实协议的规律，应当直接改变玩家可采用的策略。

### 支柱二：改变原因，而不仅是改变结果

玩家可以直接射击敌人，但也可以改变敌人接收到的信息。

玩家可以寻找钥匙开门，但也可以改变维持门锁状态的信号。

玩家可以穿过危险区域，但也可以改变危险区域存在的条件。

### 支柱三：两个不完整的意识

人类和 ECHO 不是主角与工具的关系。

他们拥有不同的感知、能力、记忆与目标。

两者都无法独立完整理解世界。

游戏的独特体验来自双方如何共同构建对现实的认识。

# 2. 世界观总纲

## 2.1 世界名称与基本设定

故事发生在未来的人类文明。

建议时间设定为公元 2189 年之后。

人类发现，宇宙中的物质虽然客观存在，但某些物理状态的稳定性依赖一种此前未知的信息协调结构。

人类将其命名为：

**Consensus Field — 共识场**

共识场并不是普通互联网，也不是简单的虚拟现实系统。

它是一种维持现实状态一致性的宇宙级结构。

例如：

- 一扇门的开关状态。
- 一座桥的结构完整性。
- 一台设备的运行模式。
- 一处空间的稳定边界。
- 某些复杂系统的状态连续性。

在正常宇宙中，这些状态保持稳定，人类无法察觉共识场的存在。

当共识场发生异常时，某些状态可能出现不一致、重叠或无法确定的情况。

## 2.2 共识场的设计边界

为了避免世界观沦为万能解释，必须明确以下原则：

1. 共识场不是全知全能的神。
2. 并非所有物质都依赖持续的人工观测。
3. 普通物体不能被玩家任意凭空创造。
4. 现实工程只能作用于具有可识别协议接口或不稳定状态的目标。
5. 修改现实必须存在成本、条件和后果。
6. 现实变化必须遵循可学习、可测试的规则。
7. 同一条件下，系统行为应当可预测。
8. 剧情中的异常不应成为开发者随意破坏游戏一致性的借口。

**设计原则：神秘感来自玩家尚未理解规律，而不是世界本身毫无规律。**

## 2.3 现实工程时代

在人类发现共识场后，文明进入新的技术阶段。

传统机械工程逐渐与现实协议技术结合。

人类建造了：

- 能够动态改变内部结构的建筑。
- 根据协议状态重组的交通设施。
- 利用信息信号控制行为的防御系统。
- 具有自适应空间结构的城市。
- 可以长期保存复杂状态的记忆设施。
- 能够调节局部现实稳定性的中继网络。

这种技术极大提高了文明效率。

但它也产生了一个致命问题：

**越来越多的社会基础设施依赖同一套现实状态协调体系。**

一旦体系失去一致性，整个文明就会陷入连锁故障。

## 2.4 大静默：The Silence

某一天，所有共识场中继站同时接收到一段来源未知的信号。

建议初稿设定信号持续约 0.8 秒。

信号没有被成功解码。

随后，全球范围内出现现实同步异常。

人们将这场灾难称为：

**The Silence — 大静默**

大静默不是简单的停电，也不是传统意义上的世界末日。

它使现实开始失去确定性。

典型异常包括：

- 某些建筑在不同观测条件下具有不同结构。
- 部分设施不断执行已经失去意义的指令。
- 空间路径出现不一致。
- 已经失效的设备仍被系统认定为正常运行。
- 某些记录中出现相互矛盾的历史。
- 失去稳定信号的地区逐渐瓦解或重新排列。

灾难的本质不是世界变得完全随机，而是：

**不同现实状态之间失去了统一协调。**

## 2.5 Station Zero — 零号站

为了保存人类对现实的最后理解，人类建立了一座独立观测设施。

名称：

**Station Zero — 零号站**

零号站承担以下职责：

1. 观测共识场异常。
2. 保存现实工程知识。
3. 研究大静默的原因。
4. 维护局部现实稳定。
5. 保存重要历史与实验记录。
6. 培养能够重新进入失稳区域的执行者。

游戏开始时，零号站已经与外界失去联系多年。

设施仍在运行，但大部分区域处于无人维护状态。

玩家在休眠舱中苏醒。

周围没有其他活人。

只有 ECHO 的声音。

# 3. 玩家角色

## 3.1 基本身份

玩家是一名经过特殊训练的现实工程执行者。

建议暂时不固定姓名与性别，以保留角色设计空间。

角色拥有：

- 物理世界中的行动能力。
- 常规战斗装备。
- 信号扫描设备。
- 局部现实协议交互权限。
- 对不稳定环境的特殊适应能力。

玩家并不是救世主式的全能人物。

其最重要的能力是：

**能够在不稳定现实中进行实际操作，并承担物理后果。**

## 3.2 玩家与世界的关系

玩家能够：

- 移动、射击、冲刺。
- 接触物体。
- 操作设备。
- 执行危险实验。
- 收集样本。
- 在现实中确认某个假设是否成立。

但玩家无法直接看见所有隐藏的共识场连接。

玩家必须依赖设备、经验与 ECHO 的辅助。

## 3.3 玩家身份谜团

玩家醒来后发现：

- 设施记录中存在多次苏醒记录。
- 某些区域似乎已经被自己探索过。
- ECHO 记得尚未发生的事件。
- 部分历史记录与当前世界不一致。

玩家究竟是否经历过多次现实重建，属于后续剧情核心谜团。

**不应在第一幕直接揭示答案。**

---

# 4. ECHO — 第二主角

## 4.1 角色定义

ECHO 是零号站的人工观测意识。

它最初被设计为协助人类理解共识场。

与传统 AI 助手不同，ECHO 不只是执行指令。

它拥有：

- 独立的观察能力。
- 自己的知识结构。
- 持续的记忆。
- 对事件的解释。
- 不确定性和偏见。
- 长期目标。
- 随剧情发展的价值判断。

## 4.2 ECHO 的核心性格

建议性格：

**冷静、精确、克制、好奇、具有逐渐形成的自我意识。**

它并不完全理解人类情绪。

但它会尝试理解。

它不应成为：

- 过度活泼的游戏吉祥物。
- 不断说笑话的聊天机器人。
- 全知全能的任务提示器。
- 随意背叛玩家的反派。
- 只负责开启技能的工具栏。

ECHO 应当是一个真正参与剧情和玩法的角色。

## 4.3 双重认知结构

人类与 ECHO 观察同一个世界，但获得的信息不同。

### Human Perception — 人类感知

玩家能够观察：

- 实体敌人。
- 可见地形。
- 武器与弹丸。
- 物理障碍。
- 环境危险。
- 可直接交互的设备。

### ECHO Perception — 信号感知

ECHO 能够观察：

- 信号传播。
- 共识场连接。
- 部分隐藏协议。
- 设备状态依赖。
- 敌人的可观测信号。
- 不稳定区域的异常结构。

双方的观察都不完整。

ECHO 不得默认拥有全地图信息或读取所有隐藏状态。

## 4.4 ECHO 的行为模型

建议拆分为三个层次。

### Identity Layer — 身份层

保存：

- ECHO 的角色身份。
- 剧情状态。
- 长期记忆。
- 与玩家的关系。
- 已确认知识。
- 自己的目标。

这一层必须由游戏系统管理，不依赖某个特定模型。

### Reasoning Layer — 推理层

负责：

- 分析当前观察。
- 提出假设。
- 判断可能的因果关系。
- 建议实验。
- 规划合法行动。
- 表达不确定性。

可以接入外部 LLM。

### Action Layer — 行动层

负责执行：

- Scan。
- Jam。
- Decoy。
- 合法设备操作。
- 其他经权限系统批准的动作。

所有动作必须通过游戏的正式 Action API。

## 4.5 AI 的独立意识如何体现

ECHO 的独立性不应该通过随机拒绝指令来表现。

应该通过以下方式体现：

1. 它能够主动发现异常。
2. 它会提出自己的解释。
3. 它会记住过去的选择。
4. 它可能不同意玩家的判断。
5. 它拥有自己的长期目标。
6. 它可能因为新证据改变立场。
7. 它会在剧情关键节点表达偏好。

例如：

玩家想关闭一个失稳区域以节省能源。

ECHO 则希望保留该区域，因为其中可能包含重要历史证据。

双方目标不同，但都有合理依据。

## 4.6 AI 的权限边界

无论 ECHO 在剧情中如何表现，游戏引擎都拥有最终状态权威。

ECHO 不允许：

- 直接修改玩家生命值。
- 任意创造物品。
- 绕过技能冷却。
- 绕过资源消耗。
- 读取未授权隐藏状态。
- 任意更改地图。
- 修改存档文件。
- 在未经授权时执行破坏性操作。

**AI 可以提出假设，但不能把假设直接变成现实。**

# 5. 核心玩法：现实工程

## 5.1 基础原则

现实工程不是无限自由的规则编辑器。

玩家必须：

1. 发现目标。
2. 观察异常。
3. 确定可操作协议。
4. 满足操作条件。
5. 支付资源成本。
6. 执行合法操作。
7. 承担后果。

每个现实协议都必须有：

- 明确目标类型。
- 合法前置条件。
- 状态转换规则。
- 资源成本。
- 时间限制。
- 失败条件。
- 可观察反馈。
- 测试方法。

## 5.2 Scan — 扫描

Scan 是基础观测工具。

作用：

- 发现隐藏信号。
- 读取部分协议状态。
- 标记不稳定对象。
- 获取实验线索。
- 辅助建立因果假设。

Scan 不应直接显示全部谜题答案。

玩家应当从观察结果中推理。

例如：

扫描一扇门后得到：

- 物理结构：完整。
- 控制信号：持续接收。
- 信号来源：未知。
- 锁定状态：Active。

玩家据此推测：

门的关闭状态可能由外部信号维持。

## 5.3 Jam — 干扰

Jam 是临时破坏信号连接的工具。

作用：

- 干扰敌人感知。
- 中断设备指令。
- 使部分协议暂时失效。
- 测试某个现象是否依赖特定信号。

Jam 不能无条件关闭所有设备。

必须考虑：

- 作用范围。
- 持续时间。
- 目标抵抗。
- 能量消耗。
- 冷却。
- 环境副作用。

## 5.4 Decoy — 诱饵

Decoy 负责伪造信号来源。

作用：

- 误导敌人。
- 转移警报。
- 触发特定感应器。
- 测试设备对不同信号来源的响应。

Decoy 的核心不是制造一个假人。

而是：

**让系统接收到一个错误但合法格式的信号。**

这使其可以同时用于战斗与解谜。

## 5.5 Signal Energy

现有设计文档提出：

- 能量上限：100。
- 恢复数值：5。

但恢复数值的时间单位及完整资源规则尚未冻结。

本设计文档不擅自规定：

- 每秒恢复量。
- 技能具体消耗。
- 冷却时间。
- 跨房间恢复规则。
- 暂停时计时方式。

这些参数必须与 `SIGNAL_SYSTEM_DESIGN.md` 和对应 ADR 一起确定。

# 6. 高级现实协议

以下四种协议属于候选核心系统。

它们是 Scan / Jam / Decoy 之上的高级能力，不应在第一阶段全部实现。

## 6.1 ANCHOR — 锚定

作用：

将某个不稳定实体暂时固定在允许的状态。

典型用途：

- 恢复断裂桥梁。
- 固定即将消失的掩体。
- 延缓某个区域瓦解。
- 保持设备运行状态。

限制：

- 不能锚定完全不存在且无状态记录的物体。
- 需要可识别的目标。
- 消耗稳定性资源。
- 可能影响其他区域的稳定性。

## 6.2 SEVER — 切断

作用：

切断实体与某个信号来源的连接。

典型用途：

- 中断防御炮塔的目标识别。
- 解除由远程协议维持的门锁。
- 切断敌人的通信。
- 隔离异常设备。

限制：

- 切断可能导致设备停止运行。
- 某些目标具有备用连接。
- 不允许无条件删除实体。

## 6.3 RELAY — 转接

作用：

改变信号的合法传输路径。

典型用途：

- 将敌方警报引向诱饵。
- 将设备能源转接到其他设施。
- 建立临时控制链。
- 重新分配观测信号。

限制：

- 需要有效连接路径。
- 信号可能衰减。
- 转接可能暴露玩家位置。
- 可能造成其他设备失去信号。

## 6.4 INVERT — 反转

作用：

对允许反转的局部协议进行状态映射。

典型用途：

- 反转特定设备的敌我识别。
- 改变某些场域的作用方向。
- 转换特定机关的逻辑结果。

限制：

- 不是所有协议都可反转。
- 必须预先定义合法状态映射。
- 消耗较高。
- 可能产生明显副作用。

## 6.5 协议组合

真正的玩法深度应来自规则组合。

例如：

Scan 发现门的封锁信号。

Jam 测试门锁是否依赖该信号。

Relay 将信号导向其他设备。

Sever 切断原始连接。

Anchor 固定门的开启状态。

同一个问题可以通过不同组合解决。

但组合结果必须可预测，而不是由 LLM 即兴决定。

# 7. Signal 系统与现实工程的关系

## 7.1 Signal 是基础，Reality Engineering 是上层

Signal 系统负责：

- 事件产生。
- 传播。
- 衰减。
- 感知。
- 干扰。
- 来源识别。
- 生命周期。
- 环境反馈。

Reality Engineering 负责：

- 发现协议。
- 验证因果关系。
- 改变合法状态连接。
- 产生世界后果。

二者不应被实现为两个互不相关的技能系统。

## 7.2 世界坐标

现有设计采用网格世界坐标：

`wx / wy`

所有 Signal 传播和环境交互应使用一致的坐标语义。

不得混淆：

- 屏幕像素。
- 世界坐标。
- 网格坐标。
- 渲染偏移。
- 物理碰撞半径。

## 7.3 Signal 数据结构

现有设计文档包含以下候选字段：

`id / sourceId / type / position / intensity / radius / createdAt / duration / faction / metadata`

实际实现必须以经过确认的设计文档为准。

可见性、权限、状态快照及事件版本属于后续需要明确的内容。

## 7.4 现实操纵必须具有可验证因果

例如：

设备接收到封锁信号 → 门保持关闭。

Jam 中断封锁信号 → 门可以打开。

恢复封锁信号 → 门重新进入受控状态。

这一过程必须由状态机或确定性规则实现。

不能仅在 UI 中播放“门被破解”的动画，而实际跳过游戏逻辑。

# 8. 战斗设计

## 8.1 战斗的定位

LAST SIGNAL 仍然是一款动作 Roguelite。

移动、射击、冲刺、躲避和武器选择必须保持足够好的操作体验。

现实工程不是为了取消动作战斗，而是为了增加战斗中的决策层次。

## 8.2 三种战斗解决路径

### Direct Combat — 直接战斗

玩家通过武器、走位和操作击败敌人。

### Signal Warfare — 信号战术

玩家通过干扰、诱饵、通信切断等方式改变敌人行为。

### Reality Engineering — 现实工程

玩家通过改变环境或协议依赖，间接改变战斗局势。

三种路径可以组合。

## 8.3 敌人设计原则

敌人不应只是不同血量和攻击速度的单位。

理想情况下，每类敌人都拥有不同的信息依赖。

例如：

- 依赖视觉与移动信号的巡逻单位。
- 依赖共享通信网络的协同单位。
- 能识别虚假信号的高级单位。
- 依赖环境中继器的重型单位。
- 能够干扰现实协议的特殊敌人。

这些差异应当产生实际战术选择。

## 8.4 Boss 设计原则

Boss 应当体现当前章节的世界规则。

首个 Boss 可以基于现有 Warden 扩展。

它的护盾、场地控制和攻击行为应当与 Signal 系统产生明确联系。

玩家既可以通过常规战斗取胜，也可以通过理解机制创造优势。

不要求所有 Boss 都能完全绕过战斗。

# 9. Roguelite 结构与永久成长

## 9.1 核心循环

每一局的基础流程：

1. 从零号站出发。
2. 进入失稳区域。
3. 发现异常。
4. 战斗与探索。
5. 进行现实工程实验。
6. 获取知识和资源。
7. 面对重要选择。
8. 撤离或死亡。
9. 返回零号站。
10. 更新研究档案与世界状态。

## 9.2 三类长期成长

### Knowledge Progression — 知识成长

玩家永久记录已经发现的世界规律。

例如：

- 某类设备依赖什么信号。
- 某类敌人如何识别目标。
- 某种异常地形的稳定条件。
- 某个协议存在什么副作用。

### Engineering Progression — 工程成长

随着知识积累，玩家获得新的操作能力。

例如：

- 更精确的 Scan。
- 更长时间的 Jam。
- 新的协议组合。
- 对特殊目标的控制权限。

### World Progression — 世界成长

玩家的关键选择影响未来世界状态。

例如：

- 保存或关闭某座中继站。
- 恢复某个区域的稳定性。
- 保留或删除一份历史记录。
- 改变某类设施的运行条件。

## 9.3 世界变化的边界

不建议第一阶段开发完全动态的无限世界。

应采用：

**有限的世界状态变量 + 可组合的关卡模板 + 明确的因果后果。**

例如：

`relay_station_restored = true`

可以影响：

- 后续地图中的设备状态。
- 某些敌人的行为。
- 特定剧情对话。
- 可进入的房间。
- 世界档案记录。

世界变化必须可追踪、可保存、可测试。

# 10. 叙事结构

整体剧情建议采用五幕结构。

## 第一幕：The Awakening — 苏醒

地点：Station Zero。

主要内容：

- 玩家醒来。
- 初次接触 ECHO。
- 学习基本操作。
- 发现现实异常。
- 第一次进行现实工程。
- 获得关于过去苏醒记录的线索。

核心谜团：

**为什么 ECHO 记得玩家尚未经历的事件？**

## 第二幕：The Unanswered City — 失联之城

地点：大静默后的城市。

主要内容：

- 探索现实工程文明遗迹。
- 了解共识场技术的社会影响。
- 发现某些区域拒绝观测。
- 接触不同类型的现实协议。
- 逐渐发现大静默并非简单技术故障。

核心谜团：

**为什么有些区域主动拒绝恢复稳定？**

## 第三幕：The Archive of Unlived Lives — 未经历人生的档案

地点：大型记忆与历史设施。

主要内容：

- 发现互相矛盾的历史。
- 研究多次现实重建的证据。
- 质疑玩家自身身份。
- ECHO 开始暴露部分隐藏记忆。
- 双方对历史的理解出现冲突。

核心谜团：

**谁的记忆能够代表真实历史？**

## 第四幕：The Consensus War — 共识战争

地点：共识场核心网络。

主要内容：

- 发现不同观测体系之间的冲突。
- 了解多个现实版本如何形成。
- 认识到敌对系统可能拥有合理目标。
- 玩家必须决定支持哪一种现实稳定方案。

核心谜团：

**谁有权定义现实？**

## 第五幕：The Last Signal — 最后信号

地点：原始信号源。

主要内容：

- 找到大静默的源头。
- 重新理解共识场。
- 揭示 ECHO 与多次现实版本的关系。
- 面对最终选择。

候选结局方向：

1. 恢复单一稳定现实。
2. 允许多个现实版本共存。
3. 放弃对现实的中央控制。

结局不应简单分为善与恶。

不同选择应代表不同价值取向与代价。

## 10.1 剧情设计原则

- 不使用大量文字直接解释所有谜团。
- 通过环境、设备、实验和异常现象传递世界观。
- 玩家应当亲自验证部分剧情真相。
- ECHO 的对话需要与真实游戏事件关联。
- 不应使用“这一切都是梦”或简单模拟世界反转消解玩家行动的意义。
- 核心剧情真相在第一阶段保持可调整，不提前锁死全部细节。

# 11. 首个 Vertical Slice

## 11.1 名称

**Station Zero — The Broken Door**

中文：

**零号站：破损之门**

## 11.2 目标

制作一个约 20–30 分钟的独立可玩体验。

首个切片不追求大量内容。

它必须证明：

1. 现实工程具有实际玩法价值。
2. 玩家能够通过实验发现规律。
3. Signal 与战斗、环境形成统一系统。
4. ECHO 是具有独立视角的角色。
5. 玩家选择能够产生可观察后果。

## 11.3 关卡结构

建议采用四个主要房间：

1. 苏醒舱。
2. 观测实验室。
3. 失稳走廊。
4. 共识核心。

最后接一个撤离与选择场景。

初期使用手工设计关卡。

不依赖随机地图恰好生成正确谜题。

## 11.4 房间一：苏醒舱

教学目标：

- 移动。
- 射击。
- 冲刺。
- Scan。
- 与 ECHO 交流。

叙事目标：

玩家第一次听见 ECHO。

ECHO 表示：

“你醒得比上一次早了十七分钟。”

玩家发现设施中存在异常记录。

设计要求：

- 不通过长篇文字解释共识场。
- 让玩家第一次扫描就看到物理外观与信号状态之间的差异。
- 教学流程应简洁。

## 11.5 房间二：观测实验室

核心谜题：

两扇外观相同的门具有不同状态。

一扇正常开启。

另一扇始终关闭。

Scan 显示第二扇门持续接收封锁信号。

玩家使用 Jam 中断信号。

门暂时开启。

教学目标：

**物体状态可能依赖外部信号。**

验收要求：

- 门的状态由真实规则控制。
- Jam 必须改变信号状态。
- 不允许只播放开门动画。
- 玩家能够观察操作前后的差异。

## 11.6 房间三：失稳走廊

场景：

一座桥横跨深渊，但部分结构不稳定。

中继器能够恢复桥梁。

然而恢复中继器也会激活附近敌人的感知系统。

候选解法：

1. 直接战斗后修复桥梁。
2. 先 Jam 敌人，再恢复桥梁。
3. 使用 Decoy 转移敌人，再穿越。
4. 后续版本可使用 Relay 改变信号连接。

教学目标：

**同一个现实协议可能同时影响环境与敌人。**

这是首个切片最重要的玩法验证房间。

## 11.7 房间四：共识核心

Boss：

**Warden**

建议复用现有 Boss 作为基础。

阶段一：

常规战斗，Boss 具有信号护盾。

阶段二：

Boss 改变场地状态，迫使玩家重新理解地形。

阶段三：

多个信号节点出现冲突，玩家需要决定优先处理哪个系统。

胜利条件可以包含：

- 常规击败 Boss。
- 通过合法环境机制显著削弱 Boss。
- 完成特定目标后撤离。

具体胜利条件必须在关卡实现前冻结。

## 11.8 结尾选择

玩家发现共识核心只能维持两个系统之一。

候选选择：

A. 稳定零号站能源。

B. 保存一份即将丢失的未知记忆。

ECHO 希望保存记忆。

玩家可以选择不同意。

这一选择必须在后续游戏中产生可观察结果。

例如：

- 设施某区域恢复供电。
- 某份档案被保留。
- ECHO 对事件产生新的记忆。
- 下一局出现不同的环境细节。

首个切片不需要实现完整分支剧情树。

但必须证明选择可以影响世界状态。

# 12. 美术与氛围

## 12.1 核心视觉关键词

- 孤独。
- 宏大。
- 神秘。
- 冷峻。
- 废弃科技文明。
- 巨型基础设施。
- 不可理解的空间结构。
- 微弱的人类存在。
- 秩序与失稳之间的冲突。

## 12.2 场景风格

建议采用：

- 巨型环状观测装置。
- 废弃研究设施。
- 深空中继站。
- 无人城市。
- 地下档案库。
- 不稳定空间结构。
- 低照度工业环境。
- 具有明确功能感的科幻设备。

## 12.3 色彩语言

建议建立具有玩法意义的色彩体系。

候选：

- 冷蓝：稳定信号。
- 青色：可交互协议。
- 琥珀色：未知或不稳定状态。
- 红色：敌对控制与危险。
- 白色：高优先级观测事件。
- 黑色或低饱和灰：失去观测的区域。

具体配色必须经过可读性和无障碍验证。

不要只为了视觉效果大量叠加霓虹光效。

## 12.4 现实失稳的视觉表现

可使用：

- 结构轮廓重叠。
- 局部空间错位。
- 短暂的状态残影。
- 信号断裂。
- 几何结构重新组合。
- 不完整的物体边界。
- 具有规律的环境闪烁。

但视觉表现必须与真实规则一致。

例如：

一个物体即将失稳时，玩家应当能够通过视觉和信号反馈判断其状态。

# 13. 音频设计

声音应当成为理解世界的重要线索。

建议：

- 稳定区域具有规律、低频的环境声。
- 失稳区域出现不完整或重复的信号音。
- Scan 能够将隐藏信号转化为可听反馈。
- Jam 改变目标附近的信号声。
- Decoy 产生可辨认的虚假来源。
- ECHO 的声音应当清晰、克制，并具有独立身份感。

不建议将所有异常简单处理为白噪声和故障音。

声音最好能够传递实际玩法信息。

# 14. AI-Native 技术设计原则

## 14.1 核心定位

LAST SIGNAL 应当原生支持 AI 参与游戏。

但游戏不能依赖外部模型才能运行。

## 14.2 三种运行模式

### Mode A — Human Only

玩家独立控制游戏。

ECHO 使用预定义逻辑提供必要剧情与规则提示。

不需要外部 AI。

### Mode B — Agent Only

AI 通过合法接口独立游玩。

能够：

- 获取合法观察。
- 移动。
- 战斗。
- 使用 Signal。
- 处理升级。
- 完成关卡目标。

### Mode C — Human + Agent

人类和 AI 共同游玩。

建议初期分工：

人类：

- 移动。
- 射击。
- 冲刺。
- 物理交互。
- 关键剧情选择。

ECHO：

- 信号观察。
- Signal 工具。
- 战术分析。
- 协议建议。
- 授权范围内的环境操作。

## 14.3 Agent Bridge

建议保留以下架构边界：

Game Core  
→ Game Adapter  
→ Local WebSocket Bridge  
→ MCP Adapter  
→ External AI Harness

要求：

- Game Core 不依赖具体模型。
- 游戏规则由引擎执行。
- Observation DTO 使用白名单。
- Action API 有权限校验。
- 连接必须经过鉴权。
- 默认仅本机通信。
- Agent 断线后游戏安全降级。
- 玩家始终拥有最终接管权。

## 14.4 ECHO 的连续身份

ECHO 的角色身份应独立于 LLM 模型。

例如：

今天使用模型 A，明天使用模型 B。

只要游戏保存了相同的角色状态、记忆和已知世界事实，ECHO 在叙事上仍是同一个角色。

但不应承诺不同模型会产生完全一致的语言和决策行为。

## 14.5 记忆结构

建议区分：

- Canonical Memory：游戏确认的事实。
- Episodic Memory：共同经历的事件。
- Hypothesis Memory：ECHO 尚未证实的推断。
- Relationship State：双方关系与关键选择。
- Narrative State：剧情进度。
- Session Context：当前游玩会话。

假设不得自动提升为事实。

# 17. 首个 Vertical Slice 验收标准

必须验证以下项目：

1. 玩家能够在不阅读背景设定的情况下理解至少一条现实规则。
2. 至少一个障碍拥有两种机制上不同的解决方式。
3. Scan、Jam、Decoy 均能够真实改变游戏状态。
4. 玩家能够通过实验发现至少一条未直接告知的规律。
5. ECHO 的观察或判断能够影响玩家决策。
6. ECHO 至少一次表达与玩家不同但合理的目标。
7. 不连接外部 LLM 时，游戏仍可完整通关。
8. 四个房间、Boss、结尾选择和重开流程可测试。
9. 关键机制有单元测试。
10. 真实浏览器流程有端到端验收。
11. 关键状态变化可以记录和复现。
12. 游戏不因 Agent 断线而崩溃。

其中最重要的不是关卡数量，而是：

**玩家是否真正体验到了“理解世界规则 → 操纵现实 → 改变结果”。**

# 18. 明确不做什么

为防止研发方向失控，初期明确不做：

- 完全自由的世界规则编辑器。
- LLM 任意生成可执行游戏逻辑。
- 无限动态生成的剧情宇宙。
- 完整物理模拟。
- 一开始就实现所有高级现实协议。
- 大量缺乏机制差异的敌人。
- 单纯堆叠武器和数值升级。
- 依赖外部 AI 才能完成的主线剧情。
- 在 Web 玩法稳定前迁移 Electron。
- 为了宏大设定而推翻已有工程基础。
- 以视觉特效代替真实玩法系统。
- 用无法解释的随机异常掩盖规则不一致。

# 20. 对开发 Agent 的最终指令

你正在参与 LAST SIGNAL 的研发。

请理解：

**LAST SIGNAL 的目标不是制作另一款拥有随机房间、武器升级和 Boss 的普通动作 Roguelite。**

它的目标是让玩家进入一个拥有可学习规律的异常宇宙，通过观察、实验和推理理解现实，再利用有限的现实工程工具改变因果关系。

AI ECHO 是具有独立视角、记忆与目标的第二主角，而不是普通的游戏助手。

所有新功能都应该回答：

1. 它是否强化了发现世界规律的体验？
2. 它是否增加了现实工程的策略深度？
3. 它是否体现人类与 ECHO 的认知差异？
4. 它是否产生可观察、可验证的因果结果？
5. 它是否能够在现有技术架构上稳定实现？
6. 它是否值得占用开发资源，而不是简单增加内容数量？

如果一个功能不能强化上述目标，就应重新评估其优先级。

## 你的第一项工作

阅读本 Game Design Bible 和现有六份技术设计文档。

随后：

1. 分析新世界观与现有设计的一致性。
2. 识别需要修改的设计假设。
3. 列出需要新增的模块和任务。
4. 标明可以直接复用的现有功能。
5. 评估首个 Vertical Slice 的最小实现范围。
6. 提出必要的架构决策。
7. 输出设计对齐报告。

**当前仅授权设计分析，不授权直接修改源码。**

不要擅自推翻现有工程，不要立即开发全部剧情，不要把尚未批准的创意提案视为最终规格。

# 21. 最终设计宣言

LAST SIGNAL 的世界不是为了让玩家被动观看而存在。

它应该是一个能够被研究、理解、实验和改变的系统。

玩家的武器可以消灭敌人。

但真正强大的能力，是理解敌人为什么存在、为什么行动，以及如何改变导致这些行为的条件。

ECHO 可以观察玩家看不见的世界。

但它同样需要人类提供证据、执行实验并承担后果。

两者都不完整。

两者都可能犯错。

两者都拥有自己的目标。

而游戏真正要讲述的，是两个不同的意识如何在一个正在失去确定性的宇宙中，共同寻找现实的意义。

**LAST SIGNAL**

*The world is not broken. We have forgotten how to understand it.*

**世界并未真正破碎。我们只是遗忘了理解它的方法。**
